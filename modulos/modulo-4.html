Desenvolvimento, Arquitetura e Validação

Agora você entra na construção técnica: stack, arquitetura, integração, boas práticas e testes que verificam se o software realmente funciona.

1. Desenvolvimento e definição da stack

Definir a stack significa estabelecer as tecnologias que a equipe vai usar. Nas anotações, aparecem linguagem, framework, banco de dados e nuvem como partes da decisão.

LinguagemEx.: Java, Python, JavaScript.
FrameworkEstrutura e bibliotecas que aceleram o desenvolvimento.
SGBDSistema de gerenciamento de banco de dados.
NuvemInfraestrutura e serviços hospedados, como os usados em provedores cloud.
Padronização: também é importante definir ferramentas de trabalho da equipe, IDE, plugins, sistema operacional e fluxo de Git.

2. Arquitetura: MVC, serviços e integrações

Arquitetura descreve como as partes do sistema se organizam e se comunicam. Suas anotações citam MVC, serviços, mensageria, APIs externas, segurança e metodologia de desenvolvimento.

3. Boas práticas

Clean CodeEstrutura legível e fácil de manter.
Code StylePadronização de formatação e convenções.
Git / GitHubControle de versão e colaboração.
GitHub ActionsAutomação de fluxos como build, testes e verificações.

Também entram aqui padrões de commit, cobertura de testes e refatoração.

4. Refatoração

Refatoração é alterar a estrutura interna do software para deixá-lo mais legível e fácil de manter, sem mudar o comportamento externo observado pelo usuário.

Em Engenharia de Software, refatorar não é “reescrever por reescrever”. É melhorar a estrutura para reduzir custo de manutenção e facilitar futuras alterações.

5. Validação de software

O material define a validação como teste do programa por meio de simulações. Ele também ressalta que os testes não devem ser monolíticos e que softwares personalizados podem exigir dados reais para os testes.

UnitárioTesta uma unidade pequena e focada, como uma função de cadastro.
IntegraçãoVerifica a comunicação entre módulos, banco ou serviços.
PerformanceAvalia comportamento sob carga e uso intenso.
BetaGrupo menor de pessoas usa o software para gerar avaliação antes da ampliação da distribuição.

6. Testes não monolíticos e mocks

Um teste não monolítico é pequeno, independente e focado em uma coisa. Isso facilita descobrir qual comportamento falhou.

Mock: componente falso que imita uma dependência real, como banco de dados, API ou arquivo, de maneira controlada durante o teste.

7. Ferramentas e simulações

As anotações citam ferramentas como pytest e ferramentas de load test. A ideia é automatizar e repetir verificações para ganhar confiança no comportamento do sistema.

8. Passo a passo de aprendizagem

Desafio prático

Escolha uma funcionalidade do sistema da loja e entregue: arquitetura MVC simplificada, 1 teste unitário, 1 teste de integração e uma situação em que você usaria um mock.
