Fundamentos de Engenharia de Software

Comece pelo vocabulário e pela visão de conjunto: o que é software, o que é Engenharia de Software, como um produto evolui e quais pessoas participam das decisões.

1. O que é software?

Definição: o material da disciplina apresenta software como programa de computador mais a documentação associada, com uma determinada funcionalidade.

Essa visão é importante porque um software não é apenas o código. Documentação, decisões, regras de negócio, telas e procedimentos também fazem parte do produto que precisa ser entendido, entregue e mantido.

Software genérico x personalizado

GenéricoFeito para um conjunto amplo de clientes, como processadores de texto, editores de imagem ou sistemas de banco de dados.
PersonalizadoDesenvolvido para necessidades específicas de uma organização, domínio ou grupo de usuários.

2. O que é Engenharia de Software?

Ideia central: é a disciplina da engenharia preocupada com os aspectos da produção de software.

O objetivo não é apenas “fazer o programa funcionar”. Engenharia de Software trata de organizar atividades, pessoas, requisitos, desenvolvimento, validação e evolução para produzir um software de forma sistemática.

Conexão com o material: o professor destaca que programação estruturada, orientação a objetos e encapsulamento surgiram/ganharam força ao longo da evolução das técnicas de desenvolvimento.

3. Processo de software

Um processo de software é um conjunto de atividades relacionadas que leva à produção do software. As anotações e os slides citam entrevistas, design, protótipo, testes e manutenção, além das quatro atividades gerais: especificação, desenvolvimento, validação e evolução.

Ponto de atenção: não existe um método universal para todos os softwares. O processo varia de acordo com objetivo, usuários e contexto.

4. Conceitos que orientam um bom produto

KISS — Keep It Simple, Stupid

É a ideia de manter a solução simples. Não significa produzir algo “fraco”, mas evitar complexidade que não ajuda o usuário nem resolve a necessidade principal.

MVP — Minimum Viable Product

É a versão mínima funcional capaz de resolver a dor principal do usuário. Serve para entregar valor cedo, aprender com o uso e evitar gastar esforço em funcionalidades secundárias antes de validar o essencial.

Happy Path

É o fluxo ideal em que tudo ocorre como esperado. Ele é útil para explicar o comportamento principal, mas não representa sozinho um sistema real, pois sistemas também precisam considerar erros, entradas inválidas, indisponibilidade, cancelamentos e outros cenários.

5. Pessoas: usuário e stakeholder

Usuário é quem utiliza o sistema. Stakeholder é qualquer parte interessada que influencia ou é afetada pelo sistema. Portanto, um usuário pode ser stakeholder, mas um stakeholder também pode ser gestor, dono do produto, auditor, equipe jurídica, suporte ou outra parte interessada.

6. Interface: GUI, UI, UX e CMD

GUIInterface gráfica: elementos visuais usados para interação com o programa.
UIComo a interface é apresentada: botões, cores, ícones, fontes, menus e layout.
UXComo a experiência funciona: fluxo, facilidade de uso, pesquisa, eficiência e compreensão.
CMD / TerminalInterface textual para executar comandos e apoiar automação, desenvolvimento e servidores.

7. Passo a passo de aprendizagem

Desafio prático

Imagine um sistema para uma pequena loja. Escreva uma frase com a dor principal, proponha um MVP com 2 ou 3 funcionalidades e descreva o Happy Path de uma compra.
